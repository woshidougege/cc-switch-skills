# 工作日报 / 周报生成

## 必须先向用户索取
不要自行猜测，缺一不可：

1. **工作目录**：包含用户全部项目的目录（例：`C:\Users\63588\lenovo`）。该目录下每个含 `.git` 的子目录都是项目，**全部都要采集**。
2. **模板文件路径**：Excel 模板的绝对路径。
3. **工作日列表**：用户给出的该周期内实际上班的日期。
4. **本人的 git 作者标识**：姓名或邮箱。同一个人可能有多个标识（例：`renxp4@lenovo.com` 与 `renxiangpeng@lenovo.com`），**必须用 `git log` 的 %an/%ae 核对齐全**，否则会漏掉整块工作。

另外从用户处（或上一期报告）确认抬头信息：人员姓名、进场时间、项目名称、客户。

## 只算本人的工作
- 只保留本人作者标识的提交。**其他同事的提交一律不能写进来**——这是硬性要求，写错等于替别人汇报。
- 采集前先列出各仓库的作者分布：`git log --all --since=... --until=... --format="%an <%ae>" | Group-Object`，确认本人是否还有别的账号。
- 用 `--all` 采集：**时间范围内的提交都算**，不要按分支过滤，很多成果先落在功能分支上。主分支（例如 `ssg-sales-ops` 的 auth 服务 `auth-release`、admin 服务 `admin-release`，以及其他仓库的 `main` / `release` / `master`，各仓库不同）只用于对照，不作为过滤条件。
- 过滤 `Merge branch`、`Revert "Merge`、`index on`、`On feature/` 这类无独立工作内容的提交。

## 工作日与周的推断
- 用户给的工作日会出现跳跃，**间隔处即为周末或法定假日**，据此切分周次（例：给了 `1 2 3 4` 和 `7 8 9 10 11`，则 5、6 为周末）。
- 列表中出现的星期日（如 9/20）是调休上班，照常填写；列表中缺失的周五（如 9/25）是法定假日，不填。
- Excel 按月填：行号 = 5 + 日期（1 号在第 6 行，31 号在第 36 行）。

## 撰写内容
- **面向领导，要接地气**。写"具体做了什么、做出什么结果"，不要写"优化了机制""提升了能力"这种看不出工作量的空话。
- 好的写法：先说动作和对象，再说结果。例：`修正了 % of Tracks 的分母算法，之前算出来偏高`、`新增硬件业务汇总，按部门出销量、数量和均价`、`紧急修好了应用启动失败和问数页整页报错两个问题`。
- 避免出现类名、方法名、SQL、接口路径、框架名。
- **项目名用用户认可的业务叫法**，不要自己根据仓库名编造。采集前先跟用户确认一次。
- 同一天涉及多个项目时按项目分段，用中文分号连接。单日长度对齐历史报告（约 2~4 句）。
- 当天没有提交记录（开会、评审、联调、回归、发布验证）时，优先结合前后日期、项目上下文和已知工作写 2~4 句，尽量不编；确需补充时保持泛化，不伪造具体单号、错误码或无法佐证的影响范围。无需逐日标注哪些内容是补充生成。
- 每天工时填 `8`；加班等特殊情况按历史报告惯例处理。
- **备注列一律不填。**

## 写入 Excel
运行 `scripts/fill_timesheet.py`，传入模板、输出路径、年月、抬头信息与内容 JSON。该脚本依赖 Python 3 和 `openpyxl`；若导入失败，先提示执行 `python -m pip install openpyxl`，不要通过改脚本规避依赖。

硬性要求：
- **只能填内容，不能改格式**。加载模板后仅给单元格赋值，不新增/删除行列、不改样式、不动合并单元格。
- 必须填写抬头这几项：`人员姓名`(B2)、`进场时间`(F2)、`项目名称`(B3)、`客户`(B4)、`报告周期`(D4)。
- 标题行 A1 的月份同步更新为当期。
- 填写前先清空 6~36 行的示例内容。
- 保存后查看脚本自带的校验输出：合并区域、列宽、行高、日期列、备注列留空、公式 `=SUM(D6:D36)` 与 `=D37/8` 均需通过。

## 交付
1. **日报**：写入 Excel，保存到用户指定位置（默认桌面，命名沿用 `工作报告-联想-YYYY年MM月.xlsx`）。
2. **周报**：直接在对话中输出纯文本，按周分段列出主要工作与成果，不写文件。
3. 交付时同步说明：哪些天无提交、哪些提交未合并到主分支，以及是否有同事的工作被误纳入。

## 文件位置
- 瞬时脚本、提交导出、内容 JSON 等文件优先放目标项目的 `.tmp\`；若 `.tmp\` 会被 Git 跟踪，则改用系统临时目录。
- 跨仓库汇总、校验结果和报告中间产物放仓库外的 `reports\`，例如 `C:\Users\63588\reports\work-report-YYYYMMDD\`。
- `.tmp\` 和 `reports\` 中的文件都不得进入任何 Git 仓库，也不得被提交到 MR。
